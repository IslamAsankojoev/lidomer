# Правила для ИИ-агента

Полное ТЗ — `docs/tz.md`. Решения — `docs/decisions/*.md`. Инструкции для владельца — `docs/setup/`.

## Как работать с ТЗ

- Этапы — строго по порядку. Этап закрыт, только когда выполнены все пункты «Готово, когда».
- Задачи **Человек** не делать и не обходить: остановиться и попросить владельца.
- Задачи **Изучить**: сначала вывод в `docs/decisions/`, потом код.
- Каждый этап — отдельная ветка и PR. В начале PR — короткий план, в конце — чек-лист «Готово, когда».

## Обязательные правила

- Коммиты — только от имени владельца репозитория, **без строк `Co-Authored-By`** и прочей атрибуции ИИ (в PR тоже).
- Секреты никогда не попадают в код, git и чат. В репозитории — только `.env.example` без значений.
- Внешние системы (Meta, Ward, Bitrix24) только читаем. Единственная запись наружу — сообщения в Telegram.
- Никаких выдуманных данных: источник не ответил → «нет данных», а не ноль. Фейки — только в тестах и сидах, с пометкой.
- Во всех таблицах (кроме справочных) есть `workspace_id`; доступ всегда проверяется по нему и по роли.
- Данные браузеру отдаёт только `apps/api`. RLS в Supabase включён и закрывает всё по умолчанию.
- Деньги — целые числа в минимальных единицах + код валюты. Время — UTC; дни — в поясе компании и только функциями из `packages/shared`.
- Телефоны и имена клиентов не попадают в логи, Sentry и сообщения в мессенджеры.
- Схема БД меняется только миграциями Drizzle (`packages/db`).
- Тесты обязательны для формул, сверки, часовых поясов и клиентов внешних API.
- В `main` — только через PR с зелёным CI (lint, typecheck, test).

## Структура

```
apps/web      Next.js — кабинет (только показ и картинка отчёта)
apps/api      NestJS — интеграции, синхронизация, метрики, отчёты, задачи
packages/shared  zod-схемы, типы, формулы, форматтеры, apiFetch
packages/db      схема Drizzle, миграции, сиды
packages/config  tsconfig, eslint, prettier
supabase/     SQL для cron, очередей и Storage
```

## Команды

```
pnpm install
pnpm dev          # web :3000 + api :4000
pnpm lint
pnpm typecheck
pnpm test
pnpm db:generate  # сгенерировать миграцию из схемы
pnpm db:migrate   # применить миграции (нужен DATABASE_URL_DIRECT)
pnpm db:seed
```

Node 22 (`.nvmrc`), pnpm (через corepack).
