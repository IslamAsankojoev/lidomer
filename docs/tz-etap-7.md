# ТЗ: Этап 7 — WhatsApp, каналы отправки и новый отчёт

Nov 22, 2026 · для ИИ-агента

Продолжение [`docs/tz.md`](tz.md) в том же формате. Метки: **ИИ** — делает агент; **Человек** — делает владелец, агент останавливается и просит; **Важно** — правило, которое соблюдается везде; **Изучить** — сначала вывод в `docs/decisions/`, потом код.

## Как работать с этим ТЗ

1. Прочитать `AGENTS.md`, `apps/web/AGENTS.md` (Next.js 16: перед кодом маршрутов — доки из `node_modules/next/dist/docs/`), решения `0007` (отчёты и Telegram) и `0009` (креативы Meta).
2. Три подэтапа строго по порядку: **7.1 → 7.2 → 7.3**. Каждый — своя ветка от свежего `main` (`etap-7-1-report`, `etap-7-2-integrations`, `etap-7-3-whatsapp`) и свой PR: в начале — короткий план, в конце — чек-лист «Готово, когда». Следующий подэтап начинается после слияния предыдущего.
3. Этап 7 начат по решению владельца, не дожидаясь закрытия Этапов 5–6: там остались только проверки людьми.
4. Решения ниже уже приняты — не пересматривать. Если код мешает их выполнить, остановиться и спросить владельца.
5. Перед PR: `pnpm lint`, `pnpm typecheck`, `pnpm test` зелёные. Миграции — `pnpm db:generate`, применить `pnpm db:migrate` до слияния PR (код без колонки упадёт). Картинки отчёта (PNG и страницы PDF) — скриншотами в PR.
6. В конце 7.3 — обновить `AGENTS.md` по разделу «Что дописать в AGENTS.md».

## Что получит пользователь

- Отчёт уходит в Telegram, в WhatsApp или сразу в оба: в конструкторе галочки у групп обоих мессенджеров.
- WhatsApp подключается через Green API на странице «Интеграции». Туда же переезжает Telegram. Страница делится на «Источники данных» и «Куда отправлять отчёты»; у каждой карточки — пометка «официальный / неофициальный API» и короткая инструкция.
- Подпись к отчёту — одна строка: «📊 Итоги дня · 19 ноября». Все цифры — только в файле: так человек открывает сам отчёт.
- Картинка PNG — только главные цифры, без креативов. PDF — первая страница как картинка, дальше все креативы за период с превью, лидами, расходом, ценой лида и продажами.
- Внизу каждой страницы — «Маркетолог — почта того, кто запланировал отчёт».

## Что уже изучено: Green API и официальный WhatsApp

Перенести в `docs/decisions/0010-whatsapp-green-api.md` в начале 7.3 (контекст, решение, последствия, источники). Заново не исследовать: проверено по документации 22.11.2026.

**Как работает Green API.** Инстанс подключается к WhatsApp как ещё одно «связанное устройство» (как WhatsApp Web): в приложении WhatsApp → Связанные устройства → отсканировать QR из консоли `console.green-api.com`. Сообщения уходят от этого номера. Один инстанс — один номер. Это сторонний сервис, не Meta: WhatsApp такие подключения не разрешает, номер могут ограничить или заблокировать. У Green API есть и отдельный официальный продукт WABA (шаблоны, оплата за сообщения) — его не используем.

**Доступ.** В консоли у инстанса четыре значения: `apiUrl` (хост методов), `mediaUrl` (хост отправки файлов), `idInstance`, `apiTokenInstance`. Запрос: `{host}/waInstance{idInstance}/{метод}/{apiTokenInstance}` — **токен в пути URL**. Хосты — поддомены `green-api.com` или `greenapi.com` (есть общие `api.green-api.com` и `media.green-api.com`); брать те, что показывает консоль.

| Метод              | Запрос                                                        | Что важно                                                                                                                                                                                                                                                           |
| ------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `getStateInstance` | GET `{apiUrl}/…/getStateInstance/…`                           | `stateInstance`: `authorized` — можно слать; `notAuthorized` — номер не привязан, нужен QR; `blocked` — номер заблокирован; `suspended` (раньше `yellowCard`) — временные ограничения за спам; `starting`, `sleepMode` — запуск или выключенный телефон, до 5 минут |
| `getWaSettings`    | GET `{apiUrl}/…/getWaSettings/…`                              | `phone` — номер аккаунта (пусто, если не авторизован), `stateInstance`                                                                                                                                                                                              |
| `getContacts`      | GET `{apiUrl}/…/getContacts/…?group=true`                     | Только группы: `[{ id: "…@g.us", name, contactName, type: "group" }]`. Обновляется до 5 минут; пустой массив — повторить позже. Без `group=true` — телефонная книга номера: **не вызывать**                                                                         |
| `sendFileByUpload` | POST `{mediaUrl}/…/sendFileByUpload/…`, `multipart/form-data` | `chatId` и `file` — обязательно; `fileName` с расширением — по нему WhatsApp решает, фото это или документ; `caption` до 1024 символов. Файл до 100 МБ. Ответ: `idMessage`, `urlFile`. Доходит за 1–20 с                                                            |
| `sendMessage`      | POST `{apiUrl}/…/sendMessage/…`, JSON                         | `chatId`, `message` до 20 000 символов                                                                                                                                                                                                                              |

Id чатов: личный — `79001234567@c.us`, группа — `…@g.us`.

**Ошибки.** 401/403 — неверный токен или инстанс удалён. 466 — лимит тарифа (на Developer — только 3 чата, группы считаются). 429 — слишком часто.

**Тарифы (за инстанс в месяц).** Developer — 0 $, только 3 чата, один такой инстанс на аккаунт: для проверки. Business — 12 $, чаты без ограничений: для работы.

**Риски.** Блокировка номера. Снижают риск: отдельный номер, а не личный; номер — обычный участник групп, где отчёт ждут; не писать незнакомым людям; не делать массовых рассылок. Отчёты — несколько сообщений в день в свои группы: риск низкий, но не нулевой.

**Официальный путь — WhatsApp Business Platform (Cloud API, Meta).** Groups API: нужен Official Business Account; в группе до 8 участников; группы создаёт сам бизнес через API, участники входят по ссылке-приглашению — существующую группу клиента подключить нельзя. Номер не блокируют, но для отчётов в уже существующие группы этот путь не подходит. Когда понадобится — новый канал (например, `whatsapp_cloud`) рядом с `green_api`.

### Код-ориентиры

```ts
// packages/shared/src/reports.ts
export const CREATIVES_PER_PAGE = 8;
/** Страниц в файле отчёта: первая — главные цифры, дальше креативы. */
export function reportPageCount(creatives: number): number {
  return 1 + Math.ceil(creatives / CREATIVES_PER_PAGE);
}
/** Креативы страницы `page` (с 2-й). */
export function creativesOnPage<T>(list: T[], page: number): T[] {
  const start = (page - 2) * CREATIVES_PER_PAGE;
  return list.slice(start, start + CREATIVES_PER_PAGE);
}
```

```ts
// MembershipRepository: email, только пока человек в команде компании
async memberEmail(workspaceId: string, userId: string): Promise<string | null> {
  const rows = await this.db.execute<{ email: string | null }>(sql`
    select u.email from auth.users u
    join members m on m.user_id = u.id and m.workspace_id = ${workspaceId}
    where u.id = ${userId} limit 1`);
  return rows[0]?.email ?? null;
}
```

**Макет страницы креативов (1080×1350, фон и цвета — как у `ReportImage`).** Сверху мелко «{компания} · {отчёт} · {период}», под ним «Креативы». Дальше до 8 строк-карточек высотой около 112 px: превью 88×88 со скруглением (нет превью — номер на сером квадрате, как сейчас); в середине название и «кампания › группа» — по одной строке с многоточием; справа четыре колонки: «Лиды», «Расход» (под ним мелко «≈ N сом», если есть курс), «Цена лида», «Продажи». Расход `null` → «—» (решение 0009), не ноль. Цифры не переносятся. Внизу — `ReportFooter`. Если 8 строк не влезают — `CREATIVES_PER_PAGE = 7` и поправить тесты.

## Этап 7.3 — WhatsApp через Green API и выбор каналов

Результат: компания подключает свой WhatsApp, отмечает в конструкторе группы Telegram и WhatsApp, отчёт уходит во все отмеченные.

Начать с `docs/decisions/0010-whatsapp-green-api.md` из раздела «Что уже изучено» — до кода.

### Модель данных — одна миграция

- `INTEGRATION_TYPES` (shared) + `'green_api'`, `INTEGRATION_LABELS.green_api = 'WhatsApp · Green API'`. Drizzle сгенерирует `ALTER TYPE integration_type ADD VALUE 'green_api'` — в этой же миграции новое значение не использовать (Postgres не даёт в той же транзакции).
- shared: `DELIVERY_CHANNELS = ['telegram', 'green_api'] as const`, `deliveryChannelSchema`, `DELIVERY_CHANNEL_LABELS = { telegram: 'Telegram', green_api: 'WhatsApp' }`. db: `pgEnum('delivery_channel', DELIVERY_CHANNELS)`.
- `report_recipients`: колонка `channel delivery_channel not null default 'telegram'` (старые строки — Telegram); внешний ключ `chat_id → telegram_chats` убрать (группы WhatsApp в этой таблице не живут; принадлежность чата проверяет сервис при сохранении); уникальный индекс — `(report_id, channel, chat_id, thread_id)`.
- Строка `integrations` типа `green_api`: ключи — в `secrets_encrypted`; в `settings` открыто — `{ idInstance, phone, state, groups: [{ id, name }], groupsUpdatedAt }`. Отдельной таблицы для групп нет.
- `report_runs.deliveries[]` — поле `channel`; в `deliverySchema` — `.default('telegram')` для старых записей.

### Схемы в `packages/shared`

- `recipientSchema`: `{ channel: deliveryChannelSchema.default('telegram'), chatId: z.string().min(1), threadId: z.string().nullable() }`; у `green_api` `threadId` всегда `null` (refine).
- `greenApiHostSchema`: строка без `/` в конце; `https:`; без логина, пароля, порта, пути, query и `#`; хост подходит под `^([a-z0-9-]+\.)*(green-api|greenapi)\.com$` (без учёта регистра). Сообщение об ошибке: «Адрес из консоли Green API, например https://1234.api.greenapi.com».
- `connectGreenApiRequestSchema`: `{ apiUrl: greenApiHostSchema, mediaUrl: greenApiHostSchema, idInstance: /^\d{4,20}$/, apiTokenInstance: min(20) }`.
- `whatsappStatusSchema`: `{ status: integrationStatusSchema, state: string | null, phone: string | null, idInstance: string | null, maskedToken: string | null, groups: { id, name }[], groupsUpdatedAt: string | null, lastError: string | null }`.
- `reportTargetsResponseSchema`: `{ telegram: { configured: boolean }, whatsapp: { status: integrationStatusSchema }, targets: { channel, chatId, threadId, chatTitle, topicTitle: string | null, active: boolean }[] }`.

## Не входит в Этап 7
