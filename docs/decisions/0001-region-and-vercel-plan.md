# 0001 — Регион и тариф Vercel

## Контекст

ТЗ, раздел «Что изучить»: регионы Supabase и функций Vercel (до Этапа 0), тариф Vercel
и лимит длительности функции (до Этапа 1). Пользователи — в Бишкеке; внешние API —
Meta (глобальный), Ward (Railway), Bitrix24 (`alatoo.bitrix24.kz`), Telegram.

## Решение

**Регион:** Supabase `eu-central-1` (Frankfurt), функции Vercel `fra1` (Frankfurt).

- Ближайшие к Бишкеку площадки, общие для обоих сервисов: Франкфурт и Мумбаи.
  Магистральный трафик из Кыргызстана идёт преимущественно через Европу (Казахстан → РФ/ЕС),
  поэтому Франкфурт обычно даёт меньшую задержку, чем Мумбаи.
- Главное — api и база в одном регионе: каждый запрос api делает несколько запросов в БД.
- Задержка браузер → web не критична: страницы отдаются CDN Vercel, данные — один запрос к api.

**Тариф Vercel: Pro.**

- Hobby разрешён только для личного некоммерческого использования; отчёт для бизнеса и
  будущий SaaS — коммерческое использование.
- Fluid compute: на Hobby максимум 300 с на вызов, на Pro — до 800 с. Для `/jobs/tick`
  берём бюджет **240 с** на вызов (запас до лимита Hobby/Pro по умолчанию), порция —
  «источник × день».
- Cron Vercel не используем (у Hobby он раз в сутки) — расписание даёт Supabase Cron.

Перед оплатой сверить актуальные условия: https://vercel.com/docs/plans/hobby,
https://vercel.com/docs/functions/configuring-functions/duration.

## Последствия

- Владелец оформляет Vercel Pro (команда) до подключения реальных данных (Этап 2).
  Для каркаса (Этап 1) достаточно Hobby.
- Если позже окажется, что Мумбаи быстрее для пользователей — переезд Supabase означает
  новый проект и перенос данных; решать до Этапа 2, пока данных нет.
