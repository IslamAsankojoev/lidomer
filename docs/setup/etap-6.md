# Этап 6 — что делают владелец и маркетолог

Этап закрывается, когда **14 дней подряд** цифры кабинета сходятся с ручной сверкой маркетолога
(или расхождение объяснено), отчёты уходят в рабочую группу, а владелец бизнеса сам смотрит метрики.
Этап 5 к этому времени тоже должен быть закрыт (три утра «Итогов дня», алерт).

## 1. Ручная сверка — маркетолог, каждый день 14 дней

1. Возьмите шаблон `docs/setup/sverka-template.csv` и откройте его в Google Таблицах или Excel.
2. Каждый день добавляйте строку **за вчера** (день в формате `2026-11-18`, по Бишкеку):
   - **расход** — из Ads Manager, в валюте кабинета (USD), за этот день;
   - **реклама, органика, direct, другие** — сколько новых лидов по вашим данным (Ward, Bitrix24);
   - **продажи** — сколько сделок перешло в «Продажа»;
   - **комментарий** — всё необычное (импорт, сбой, ручные правки).
     Если что-то не считали — оставьте ячейку **пустой**, а не 0: пустое не сверяется.
3. Раз в несколько дней скачайте таблицу как CSV и пришлите файл в чат (в файле только цифры, без
   телефонов и имён — так и должно быть).

Я сравниваю её с кабинетом командой `pnpm --filter @lidomer/api sverka <файл.csv>`. Каждое расхождение —
либо исправление кода с тестом, либо объяснение в `docs/decisions/` и подсказка в интерфейсе.

Пока Meta Ads не подключена, расход не сверяется: в кабинете «нет данных».

## 2. Сторож расписания — GitHub (5 минут)

Раз в 10 минут GitHub проверяет, что фоновая работа идёт и что в базе применены все миграции кода.
Если нет — алерт в группу алертов Telegram, а если api вообще не отвечает — письмо от GitHub на вашу почту.

**Порядок выкладки, если в PR есть новая миграция** (`packages/db/migrations`): сначала `pnpm db:migrate`,
потом слияние PR. Иначе новый код api падает на ещё не созданных таблицах. Так 23.11.2026 на сутки
перестали пересчитываться лиды: сторож теперь сообщает «База отстала от кода».

1. GitHub → репозиторий **lidomer** → **Settings → Secrets and variables → Actions**.
2. Вкладка **Secrets** → **New repository secret**: имя `CRON_SECRET`, значение — то же, что в Vercel
   (проект **lidomer-api** → Settings → Environment Variables → `CRON_SECRET`). В чат не присылать.
3. Вкладка **Variables** → **New repository variable**: имя `API_URL`, значение `https://lidomer-icm7.vercel.app`.
4. После слияния PR: **Actions → watchdog → Run workflow** — запуск должен стать зелёным.
5. Проверьте, что в GitHub включены письма о сбоях Actions: аватар → **Settings → Notifications →
   Actions** → «Send notifications for failed workflows only».

## 3. Sentry — ошибки кабинета (10 минут)

1. Зарегистрируйтесь на **sentry.io**, при создании организации выберите хранение данных **в EU**.
2. Создайте два проекта: **Node.js → NestJS** с именем `lidomer-api` и **Next.js** с именем `lidomer-web`.
   Мастер установки пропустите — код уже готов.
3. В каждом проекте: **Settings → Client Keys (DSN)** → скопируйте DSN.
4. Vercel, сразу туда (в чат не присылать):
   - проект **lidomer-api** → `SENTRY_DSN` = DSN проекта `lidomer-api`;
   - проект **lidomer** → `NEXT_PUBLIC_SENTRY_DSN` = DSN проекта `lidomer-web`;
     оба — для Production → **Redeploy** обоих проектов.
5. В Sentry **не включайте** Session Replay и «Send default PII»: телефоны и имена клиентов туда
   попадать не должны.

## 4. Тарифы и резервные копии

- **Supabase → Pro.** На Free резервных копий нет. На Pro — ежедневные копии за 7 дней
  (Database → Backups). Supabase → Organization → Billing → Upgrade to Pro. После перехода откройте
  **Database → Backups** и убедитесь, что копии появляются.
- **Vercel → Pro.** Сейчас команда на Hobby, а Hobby разрешён только для некоммерческого
  использования (решение 0001). Vercel → Settings → Billing → Upgrade.

## 5. Запуск (после 14 дней сверки)

1. **Домен** (если нужен свой, например `report.lidforce.kg`): Vercel → проект **lidomer** →
   Settings → Domains → Add → прописать DNS у регистратора, как покажет Vercel. Потом скажите мне —
   я добавлю адрес в `WEB_ORIGIN` api и в настройки входа Supabase.
2. **Рабочая группа:** кабинет → Отчёты → Получатели → подключите рабочую группу (`/connect КОД`),
   в отчётах замените тестовую группу на рабочую.
3. **Владелец бизнеса:** Настройки → Команда → пригласить по email с ролью «Наблюдатель» или
   «Владелец».

## Решить владельцу
